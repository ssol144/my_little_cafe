# Firebase 설정 가이드 (Google 로그인 + 클라우드 저장)

이 게임은 **게스트로 바로 시작**하고, 원할 때 설정 화면에서 **Google 계정을 연동**해 클라우드에 저장하는 구조입니다.
Firebase 설정값이 없으면 계정 기능은 화면에 나타나지 않고, 게임은 기기 저장만으로 정상 동작합니다.

소요 시간: 약 15~20분 · 비용: 무료(Spark 요금제)로 시작 가능

---

## 1. 프로젝트 만들기
1. https://console.firebase.google.com 접속 → **프로젝트 추가**
2. 이름: `my-little-cafe` (자유)
3. Google 애널리틱스: 지금은 **사용 안 함**으로 해도 됩니다 (나중에 켤 수 있음)

## 2. Google 로그인 켜기
1. 왼쪽 메뉴 **빌드 → Authentication → 시작하기**
2. **로그인 방법** 탭 → **Google** → 사용 설정 → 프로젝트 지원 이메일 선택 → 저장

## 3. Firestore(클라우드 저장소) 만들기
1. **빌드 → Firestore Database → 데이터베이스 만들기**
2. 위치: **asia-northeast3 (서울)** ← 한 번 정하면 바꿀 수 없습니다
3. **프로덕션 모드**로 시작
4. 만들어지면 **규칙** 탭 → 저장소의 `firestore.rules` 내용을 그대로 붙여넣기 → **게시**
   - 규칙 요약: 로그인한 본인만 자기 세이브(`saves/{uid}`)를 읽고·쓰고·삭제 가능, 그 외 모든 경로 차단, 필드·크기 검증

## 4. 웹 앱 등록 → 설정값 4개
1. 프로젝트 개요 옆 ⚙ → **프로젝트 설정 → 일반 → 내 앱 → 웹(</>)**
2. 앱 닉네임 `web` → 등록 (Hosting 체크 불필요)
3. 표시되는 `firebaseConfig`에서 아래 4개를 복사
   ```
   apiKey, authDomain, projectId, appId
   ```
4. 위치별 입력
   - 로컬: `.env`의 `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID`
   - Vercel: *Settings → Environment Variables*에 같은 이름으로 등록 후 재배포

> 이 값들은 앱에 포함되는 **공개 식별자**라 노출돼도 됩니다. 데이터 보호는 3단계의 보안 규칙이 담당합니다.
> 반대로 *서비스 계정 키(JSON)*나 *Admin SDK 키*는 절대 앱·저장소에 넣으면 안 됩니다. 이 게임은 그런 키를 쓰지 않습니다.

## 5. Android 앱 등록 → google-services.json
1. **프로젝트 설정 → 일반 → 앱 추가 → Android**
2. 패키지 이름: `com.mylittlecafe.game`
3. 디버그 서명 인증서 SHA-1:
   ```
   63:C0:84:CC:DE:C8:90:2E:32:07:54:2A:77:43:CB:42:8C:C7:BF:BE
   ```
4. 등록 후 앱 설정 화면에서 **SHA-256**도 추가 (지문 추가 버튼)
   ```
   67:0A:11:EF:63:21:49:2E:5A:48:98:CB:D3:C7:CD:59:B7:D3:87:5A:DB:D1:A9:22:3D:FA:F3:BA:A3:3A:94:B6
   ```
5. **google-services.json 다운로드** → 저장소의 `android/app/google-services.json`에 넣기
   - Gradle이 이 파일이 있을 때만 Firebase 플러그인을 적용합니다. 없으면 APK는 빌드되지만 폰에서 Google 로그인이 동작하지 않습니다.
6. SDK 추가 단계(Gradle 설정 안내)는 이미 프로젝트에 반영되어 있으니 **건너뛰기**

> 위 지문은 저장소에 포함된 개발용 키(`android/app/debug.keystore`)의 값입니다. 어느 PC에서 빌드해도 같습니다.
> **스토어 출시용 키**를 만들면 그 SHA-1/SHA-256도 같은 화면에 추가해야 하고, Play 앱 서명을 쓰면 Play Console의 "앱 서명 키 인증서" 지문도 추가해야 합니다.

## 6. 승인된 도메인 (웹 로그인)
**Authentication → 설정 → 승인된 도메인**에 웹 버전 주소를 추가합니다.
- `localhost`는 기본 포함
- Vercel 배포 주소 (예: `my-little-cafe.vercel.app`), 커스텀 도메인이 있으면 그것도

## 7. 확인
- 웹: `npm run dev` → 설정 → **Google 계정 연동** → 연동 후 "저장됨 HH:MM" 표시
- Firebase 콘솔 **Firestore → 데이터**에 `saves/{사용자ID}` 문서가 생기면 성공
- Android: 저장소에 `google-services.json`이 들어간 상태에서 `npm run android:apk` → 폰에 설치 → 설정 → Google 계정 연동

## 동작 방식
| 상황 | 동작 |
|---|---|
| 게스트 | 기기에만 저장 (기존과 동일) |
| 처음 연동 | 클라우드가 비어 있으면 기기 데이터를 업로드 |
| 새 기기에서 로그인 (기기 진행 없음) | 클라우드 데이터를 자동으로 불러옴 |
| 양쪽 모두 진행 기록이 있고 다를 때 | "클라우드 / 이 기기" 중 선택 화면 |
| 업로드 시점 | 영업 정산, 앱 백그라운드 전환, "지금 클라우드에 저장", 그 외 최대 90초에 1회 |
| 추억 앨범 사진 | 용량 문제로 클라우드에 올리지 않음 (제목·내용·날짜는 저장) |
| 데이터 초기화 | 자동 로그아웃 후 기기만 초기화, 클라우드 사본은 유지 |
| 계정 삭제 | 클라우드 세이브 + 로그인 계정 영구 삭제, 기기 데이터는 유지 |

## 무료 한도 (Spark, 2026년 기준 공개 수치이며 변경될 수 있음)
| 항목 | 일일 무료 | 이 게임 사용량 추정 |
|---|---|---|
| Firestore 쓰기 | 20,000건 | 1인 1일 플레이 시 약 5~15건 → 약 1,300~4,000명/일 |
| Firestore 읽기 | 50,000건 | 접속 1회당 1건 |
| 저장 용량 | 1 GiB | 세이브 1개 약 10~60KB → 약 2만 명 이상 |
| Authentication (Google 로그인) | 소셜 로그인은 무료 구간이 넉넉함 — 정확한 한도는 콘솔 *사용량 및 결제*에서 확인 | 초기 규모에서는 비용 없음 |

한도를 넘으면 그날은 클라우드 저장이 실패하고 게임은 기기 저장으로 계속 동작합니다. 사용자가 늘면 Blaze(종량제)로 전환하면 됩니다.
